Use published: false in the page's front matter. Jekyll then doesn't build it at all — no HTML, not reachable by URL, not in the sitemap or search. The .md stays for later; set published: true (or delete the line) to bring it back.

nav: false only hides it from the navbar — the page still builds and is reachable by URL (that's what you saw).
Commenting out the page does NOT remove it: if you comment out the body, Jekyll still builds the page from its front matter and it's reachable at the URL, just blank; and you can't cleanly comment out YAML front matter. So published: false is the right tool.

3. SEO — what it is + best steps
SEO = making your site show up in Google when someone searches "Shubhro Dev", and making shared links show a rich preview (your photo + title) on LinkedIn/WhatsApp/etc.

What I just enabled (was off by default):

serve_og_meta: true + an absolute og:image (https://spearb0lt.github.io/assets/img/prof_pic.jpg) → link previews with your photo, name, and description.
serve_schema_org: true → structured data that tells Google you're a person.
(You already had a sitemap.xml, robots.txt, correct url, and keywords/description.)
Best steps to be easily findable (do these after you deploy the site live):

Deploy it (push to GitHub → GitHub Pages serves it publicly). It must be live and public for Google to index.
Google Search Console (most important):
Go to search.google.com/search-console → add property https://spearb0lt.github.io.
Verify ownership (HTML-tag method): copy the code it gives you, then set google_site_verification: <code> and enable_google_verification: true in _config.yml, redeploy, and click Verify.
Submit your sitemap: https://spearb0lt.github.io/sitemap.xml. This gets Google to crawl and index you faster and shows you search stats.
Backlinks (huge for a personal name): put your portfolio URL in your LinkedIn (Contact info + Featured), GitHub profile (website + bio), resume, ORCID, Google Scholar, ResearchGate. Search engines rank a personal site higher when trusted profiles link to it.
Optional: Bing Webmaster Tools (same idea, bing_site_verification), and Google Analytics (analytics.google) if you want visitor stats (not ranking, just tracking).


How to run the site locally, anytime
You don't have Ruby installed, so the reliable way is Docker (what we've been using):

1.Start Docker Desktop (wait until its whale icon says "running").
2.Open a terminal (PowerShell or Git Bash) and go to the repo:

cd "C:\Users\Shubhro Dev\Documents\GitHub\spearb0lt.github.io"
Start the site:

3.docker compose up -d
(If it ever tries a long build on a fresh machine, run docker pull amirpourmand/al-folio:latest once, then docker compose up -d --no-build.)
Wait ~20–30 seconds for the first build, then open http://127.0.0.1:8080/
While it's running: edit any page/content file and it auto-rebuilds (just refresh the browser). If you change _config.yml or anything in _data/, run docker compose restart to pick it up.
4.Stop it when done:

docker compose down

this theme auto-converts images (including .gif) to static .webp, and figure.liquid serves that webp. So if you use {% raw %}{% include figure.liquid %}{% endraw %} (or the project card img:), a GIF shows a frozen frame, not the animation.

GIF that actually animates → use a plain <img> (bypasses the webp pipeline). Put this anywhere in a page body (404, a project's body, etc.):


<div style="max-width: 360px; margin: 1rem auto;">
  <img src="/assets/img/spiral.gif" class="img-fluid rounded z-depth-1" alt="spiral animation" loading="eager">
</div>

For a video (put the file in assets/video/):


<video src="/assets/video/demo.mp4" autoplay loop muted playsinline width="100%"></video>
--
Video (mp4/webm) → use the theme's video.liquid include (videos aren't touched by the image pipeline). Put the file in assets/video/ and:
{% raw %}{% include video.liquid path="assets/video/demo.mp4" class="img-fluid rounded z-depth-1" autoplay=true loop=true controls=true %}{% endraw %}

raw tag if you prefer full control:
<video src="{% raw %}{{ '/assets/video/demo.mp4' | relative_url }}{% endraw %}" autoplay loop muted playsinline width="100%"></video>

On a project's card thumbnail (the img: field): because the card goes through figure.liquid, a GIF there will be static. Two ways to get animation:


Recommended: keep the card as a normal image, and show the GIF/video in the project's body with the <img>/video.liquid snippets above (that's what sites like mayankm96's do — the animation lives in the project page, not always the tiny card).
Site-wide: remove ".gif" from imagemagick.input_formats in _config.yml so GIFs are never converted; then a GIF used via figure.liquid/img: will animate (you lose webp optimization for GIFs only).
